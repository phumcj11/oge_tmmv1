# Ofero TMM System (MVP)

ระบบจัดการงาน Trade Marketing สำหรับ Ofero — เว็บแอป + ฐานข้อมูล SQLite
รวม 4 โมดูล: **Dashboard ยอดขาย/กำไร · ทะเบียน Dealer · จัดการ Event · คลัง POSM**

## วิธีรัน (ครั้งแรก)

ต้องมี **Node.js** ติดตั้งในเครื่อง (แนะนำ v18 ขึ้นไป)

```bash
cd tmm-system
npm install
npm start
```

แล้วเปิดเบราว์เซอร์ไปที่ **http://localhost:4173**

> ครั้งแรกที่รัน ระบบจะสร้างฐานข้อมูล `tmm.db` และใส่ข้อมูลตั้งต้นให้อัตโนมัติ
> (Dealer 115 ราย · สินค้า 9 รุ่น · Event 12 งาน · POSM 10 รายการ)

ครั้งต่อไปรันแค่ `npm start` พอ (ข้อมูลที่แก้จะถูกเก็บไว้ใน `tmm.db`)

## รีเซ็ตข้อมูลกลับเป็นค่าตั้งต้น

```bash
npm run seed
```

หรือลบไฟล์ `tmm.db`, `tmm.db-wal`, `tmm.db-shm` แล้วรันใหม่

## โครงสร้าง

```
tmm-system/
├─ server.js        Express API server
├─ db.js            ชั้นฐานข้อมูล SQLite + seed
├─ seed-data.json   ข้อมูลตั้งต้น (จากการวิเคราะห์ PO+Dealer+Price List จริง)
├─ tmm.db           ฐานข้อมูล (สร้างอัตโนมัติ — ข้อมูลจริงอยู่ที่นี่)
└─ public/          หน้าเว็บ (index.html, app.js, styles.css)
```

## ฟังก์ชันแต่ละโมดูล

| โมดูล | ทำอะไรได้ |
|-------|-----------|
| **Dashboard** | KPI (Sell-in / มูลค่าค้าปลีก / กำไร Dealer / ค้างชำระ), ยอดตามรุ่น/ภาค/เดือน, Top Dealer, ลูกหนี้ |
| **Dealer** | ค้นหา/กรอง, กรอกเบอร์โทร-LINE-Tier แล้วบันทึกเข้า DB |
| **Event** | ตาราง Rollout 12 งาน — อัปเดตสถานะ (วางแผน/ยืนยัน/เสร็จ/ยกเลิก), กรอก Lead + ยอดขาย |
| **POSM** | คลังสื่อ — **เบิก-คืน (ผูกกับ Event + ผู้รับผิดชอบ + กำหนดคืน)**, ประวัติการหมุนเวียนรายชิ้น, **แจ้งเตือนของใกล้หมด** (สต็อกขั้นต่ำ) และ **เกินกำหนดคืน**, มูลค่าสินทรัพย์รวม |

## หมายเหตุข้อมูล
- "ต้นทุน" ในสินค้า = ราคาที่ Dealer ซื้อจากบริษัท (= Sell-in ของเรา) · "กำไร" = กำไรของ Dealer
- ข้อมูลนี้เป็น **sell-in** (Dealer สั่งซื้อ) ยังไม่รวม sell-out/สต็อก/เป้า — ควรเก็บเพิ่มในเฟสถัดไป
- ยอด outstanding นับเฉพาะ Dealer ที่จับคู่ได้

## ต่อยอดขึ้น Server (ให้ทีมใช้ร่วมกัน)
โครงสร้างนี้ deploy ขึ้นเซิร์ฟเวอร์ได้เลย (เช่น VPS/Cloud) — เปลี่ยน SQLite เป็น PostgreSQL/MySQL เมื่อผู้ใช้เยอะขึ้น และเพิ่มระบบ login ได้ภายหลัง
